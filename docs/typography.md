# 文章排版

编辑器提供 AMD 技术蓝、极简墨色、纸感期刊、曜石青四套常用版式，覆盖标题、代码、图片说明、引用和表格。新建稿件默认使用 AMD 技术蓝。

## 四套常用版式

| 版式 | 标识 | 阅读特点 | 切换版式时的推荐组合 |
| --- | --- | --- | --- |
| AMD 技术蓝 | `technical` | 白底、官网蓝标题层级、深色代码区、浅蓝引用 | 17px 正文、代码横向滚动、表格自动适配 |
| 极简墨色 | `minimal` | 白底、克制的装饰与浅色代码区 | 16px 正文、代码阅读换行、表格自动适配 |
| 纸感期刊 | `journal` | 宋体、暖色纸感、居中标题、宽松行距 | 17px 正文、代码阅读换行、简单表格分行卡片 |
| 曜石青 | `obsidian` | 黑青底配亮青色强调，适合实验室风格 | 17px 正文、代码阅读换行、表格自动适配 |

深海青、青绿实验室与旧版雅致/简洁/留白从常用列表收起。已有稿件使用这些版式时，选择器会追加一项“已保存 · 原版式”，原 ID、元数据与历史 revision 不做迁移；切回四套常用版式后收起该兼容项。

AMD 技术蓝的默认强调色与“AMD 官网蓝”配色采用 ROCm 博客官方浅色链接蓝 `#0051C6`，暗色版式使用其暗色链接蓝 `#2899FF`，引用底色随明暗调整。来源：[官方样式表](https://rocm.blogs.amd.com/_static/custom.css?v=643846e8)。公众号参考文章仅借鉴标题、引用与留白层次，其暖橙配色未复制到技术蓝。

切换版式会加载该版式的推荐组合，随后可以单独调整六项排版设置。默认配色保留各版式的原设计；其他配色作用于标题强调、链接和相关边线，纸张与代码语法配色由版式控制。

## 六项排版设置

| 设置 | 可选值 | 用途 |
| --- | --- | --- |
| 正文字体 | 随版式、系统黑体、阅读宋体 | 随版式时，纸感期刊使用宋体，其余新主题使用黑体；实际字体取决于手机或电脑已安装的字体 |
| 正文字号 | 15、16、17、18px | 调整正文和列表文字；代码块继续使用等宽字体及独立字号 |
| 图片说明字号 | 12、13、14、15、16px，新主题默认 12px | 调整图片下方说明文字，最低 12px；旧三版式默认保留约 13px 的原有图注 |
| 表格字号 | 12、13、14、15、16px，新主题默认 13px | 调整表格及分行卡片内文字，最低 12px；旧三版式默认保留 16px，宽表格通过滚动或卡片显示完整内容 |
| 代码长行 | 横向滚动、阅读换行 | 横向滚动保留长行形态；阅读换行适合手机阅读，不改写 Markdown 中的原始代码 |
| 表格呈现 | 自动适配、保留横滑、分行卡片 | 简单短表格可直接适配；宽表格可横向滚动；简单数据表可按每行生成带字段名称的卡片 |

代码块显示语言标记，并为支持的语言应用语法高亮，包括新增的 PowerShell 语法模块。未知语言按纯文本显示。

上表的“新主题”指技术手册、纸感期刊、极简墨色、曜石青、深海青、青绿实验室。旧 `grace`、`default`、`simple` 的图片说明默认元数据为 13，保留原版式约 13px 的图注；表格默认元数据为 16。旧版式中将任一项选为 12px 都会明确应用 12px，并形成新的稿件 revision。

## 图片说明与表格

紧跟图片的 `*图 1：实验室架构。*`、`**Figure 1: Laboratory layout.**` 等编号说明，也会在预览和发布 HTML 中识别为图注，跟随图片说明字号。Markdown 原文保持不变，普通正文段落不会合并为图注。

图片说明优先取 Markdown 图片的显式 `title`，没有 `title` 时使用描述性的 `alt`。文件名形式的 `alt` 和图片路径不自动生成说明。例如：

```markdown
![多卡互联拓扑](images/topology.png "图 1：多卡互联拓扑")
```

上述图片的说明为“图 1：多卡互联拓扑”。`![topology.png](images/topology.png)` 不会把文件名显示成图片说明。没有说明文本时不额外生成占位文字。

宽表格保留全部列和单元格内容，超出可读宽度时在表格区域内横向滚动；分行卡片把简单表格的每行展开为带字段名称的记录，适合窄屏阅读。自动适配可让单元格文字换行，长字符串也应保持可查看，不用省略号或裁切隐藏内容。合并单元格、复杂表头等结构保留为可横滑表格，不强行转换为卡片。

## 手机、折叠屏与 iPad 预览

“设备预览”按普通手机、折叠屏、iPad 分组，包含 6 款手机和 2 款 iPad，共 10 个屏幕状态。新开编辑器默认 iPhone 16 竖屏；切换稿件保留当前预览选择。

| 机型 | 竖屏参考视口（CSS px） |
| --- | --- |
| iPhone 16 | 393 × 852 |
| iPhone 16 Pro | 402 × 874 |
| iPhone 16 Pro Max | 440 × 956 |
| Google Pixel 9 | 412 × 924 |
| Galaxy Z Fold5 | 外屏 344 × 882；展开内屏 690 × 829 |
| Pixel 9 Pro Fold | 外屏 412 × 922；展开内屏 836 × 842 |
| iPad mini 8.3″ | 744 × 1133 |
| iPad Air 11″ | 820 × 1180 |

Apple 尺寸参考 [Apple 布局规范](https://developer.apple.com/cn/design/human-interface-guidelines/layout)；Android 与折叠屏参考 [Chrome DevTools 设备预设](https://chromium.googlesource.com/devtools/devtools-frontend/+/60b167cf95abfe5279e0bd5bf0a2b7654b7945f6/front_end/models/emulation/EmulatedDevices.ts)，固定修订 `60b167cf95abfe5279e0bd5bf0a2b7654b7945f6`。这些是参考视口，实际可用宽度会随系统显示缩放、微信字号、多窗口等设置变化。

支持横竖屏切换。“适合面板”按机型原始视口宽度排版后缩小展示，不改写字号；“原大 100%”保留原始宽度，大屏内容可左右查看。状态栏显示当前参考宽度及显示比例。文章始终纵向滚动，不按设备高度截断正文；预览面板改变尺寸或内容载入后会重新适配。通用 320/375/430px 与 280–1600px 自定义宽度继续可用。

设备、方向和显示比例仅用于当前浏览器预览，不写入稿件、不同步到微信，也不改变六项排版设置。预览框架只在编辑器外层，导出/同步 HTML 不包含设备缩放、固定宽度或机型外壳。它用于检查排版，不模拟微信客户端字体、浏览器内核或真实折痕；最终效果仍需微信草稿预览确认。

## 兼容范围

- 支持 Markdown 标题、段落、行内代码、代码块、列表、普通引用、链接、图片和表格；提示型引用可使用 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 标记。
- 分行卡片适用于结构规则的简单表格。合并单元格、多行表头、嵌套表格、表尾或各行列数不一致时，保留表格并采用横滑，避免改变单元格关系。
- 旧稿件明确保存的 `grace`、`default`、`simple` 主题继续可用。原有四项均为随版式字体、16px、代码横滑、表格自动适配，且新增图片说明/表格字号为其默认的 13/16 时，保留原有旧主题处理与历史 revision。
- 已部署的四字段记录会按主题补上默认元数据：旧三版式为图片说明 13、表格 16；`technical`、`journal`、`minimal` 为图片说明 12、表格 13。使用这些等效默认值时保持原 revision。修改新增字号会形成新 revision；恢复其主题默认值后恢复对应的历史哈希，不需要迁移或改写旧稿件文件。
- 排版设置会随稿件保存。六字段同步请求须完整，且与已保存的主题、配色和设置一致。旧四字段请求仅在新增两项均为各主题默认值时兼容，即旧三版式 13/16、新六主题 12/13；任一新增项采用其他字号时，旧请求会收到 409，避免旧客户端覆盖新设置。检查在上传素材和创建远端草稿前完成。旧主题采用全部默认排版时仍兼容缺省排版对象的旧请求。
- 设置只接受预设字体、字号、代码和表格模式，不接受任意 CSS。自定义 HTML 或自行插入的样式不在全面兼容承诺内。

维护接口共六个字段：`font_family`（`theme/sans/serif`）、`font_size`（整数 `15/16/17/18`）、`caption_font_size`（整数 `12/13/14/15/16`）、`table_font_size`（整数 `12/13/14/15/16`）、`code_wrap`（`scroll/wrap`）、`table_mode`（`auto/scroll/cards`）。新增两项对新六主题默认 `12/13`，对旧三版式默认 `13/16`。缺省元数据对新主题使用 17px 正文、代码横滑及表格自动适配；编辑器切换版式时可应用上表中的推荐组合。

本版资源入口为 `index-20261017-code.js`，排版模块为 `typography-20261017-code.mjs`，控件资源为 `typography-controls-20261017-code.mjs` 与 `typography-controls-20261017-code.css`，对应版本 `2026.10.17-code.5`。

## AI 与 GPU 代码高亮

代码使用本地 Highlight.js 11.11.1，新增基于 Python/C++ 语法的 AI/GPU 扩展及官方 Dockerfile、CMake、LLVM IR 模块，无需联网加载。四套常用版式采用 14px 等宽代码、12px 语言栏、细边框，并分别适配深浅底色。关键字、装饰器、字符串、数值/类型、函数/API、注释分层着色。

在 Markdown 的三个反引号后填写语言：

| 内容 | 推荐标记 | 兼容标记 |
| --- | --- | --- |
| Python / PyTorch | `python` | `py`、`python3`、`py3`、`pytorch`、`torch` |
| TileLang | `tilelang` | `tile-lang`、`tile_lang` |
| Triton | `triton` | — |
| C / C++ | `c` / `cpp` | `c++`、`cxx`、`cc`、`hpp` 等原有 C++ 别名 |
| AMD HIP | `hip` | `hip-cpp` |
| CUDA | `cuda` | `cu`、`cuh` |
| PowerShell | `powershell` | `pwsh`、`ps1`、`ps`、`psm1`、`psd1` |
| Bash 脚本 | `bash` | `sh`、`zsh` |
| 带 `$` 提示符的终端记录 | `shell` | `console`、`shellsession` |
| 容器与构建 | `dockerfile` / `cmake` | `docker`、`cmake.in` |
| LLVM IR | `llvm` | `ll` |

普通 `python` 代码块也会突出常见 PyTorch/NumPy/JAX/TensorFlow 命名空间、Tensor/constexpr 等注解。TileLang 的 `T.Kernel`、`T.copy`、`T.alloc_shared`，Triton 的 `tl.load`、`tl.store`、`tl.arange`，以及 HIP/CUDA 的内核限定符、线程索引和运行时 API 有专门识别。采用词法高亮，不进行类型推断；自定义命名空间别名可能按普通标识符显示。JavaScript/TypeScript、JSON/JSONC、YAML、TOML、Rust、SQL 等已有语言继续可用。

代码横滑保留长行，换行模式只改变显示；缩进、空行、制表符及尖括号等原文保留。公众号导出将颜色转成行内样式，不依赖网页脚本或高亮类名。未填写或不支持的语言安全显示为纯文本，不自动猜测。旧三版式的默认外观保持原有处理；选用四套常用版式即可获得新代码框样式。

## ROCm 博客转载

点击左侧“导入 ROCm 博客”，粘贴 `https://rocm.blogs.amd.com/` 官方文章链接。编辑器先保存当前修改，再建立新稿；不会覆盖正在编辑的正文。导入会选取文章正文，排除站点导航、侧栏与标题锚点；将相对链接解析为绝对地址，将正文配图下载到新稿的 `images/` 下，并保留图片说明、作者、原文来源和代码语言。

代码块保留原始缩进、空行、续行和字符；正文表格使用编辑器既有的自动适配、横滑或卡片模式。Sphinx 提示框转为提示型引用。仅访问同一官方博客主机，重定向也检查；图片下载失败则不保留半成品草稿。导入后的文章仍可正常编辑与翻译。

安装版已包含解析依赖。源码运行额外执行 `python -m pip install -r requirements-rocm.txt`，不需要为了博客导入安装浏览器归档工具。

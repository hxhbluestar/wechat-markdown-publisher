# 文章排版

编辑器提供七套常用文章版式，覆盖标题、正文、代码、图片说明、引用、提示框和表格。新建稿件默认使用 AMD 技术蓝；文章版式与代码主题可分别选择。

## 七套常用文章版式

| 版式 | 标识 | 阅读特点 | 切换版式时的推荐组合 |
| --- | --- | --- | --- |
| AMD 技术蓝 | `technical` | 白底、官网蓝标题层级、深色代码区、浅蓝引用 | 17px 正文、12px 代码阅读换行、表格自动适配 |
| 极简墨色 | `minimal` | 白底、克制的装饰与浅色代码区 | 16px 正文、代码阅读换行、表格自动适配 |
| 纸感期刊 | `journal` | 宋体、暖色纸感、居中标题、宽松行距 | 17px 正文、代码阅读换行、简单表格分行卡片 |
| 曜石青 | `obsidian` | 黑青底配亮青色强调，适合实验室风格 | 17px 正文、代码阅读换行、表格自动适配 |
| 极光蓝绿 | `nord` | 灰白纸张、蓝绿层级标题、淡蓝引用和分层提示框，适合工程文档 | 17px 正文、VS Code 深色代码、阅读换行、表格自动适配 |
| 紫夜实验室 | `dracula` | 紫灰底、粉紫和亮青强调、深色引用卡片，适合实验室技术长文 | 17px 正文、Catppuccin 摩卡代码、阅读换行、表格自动适配 |
| 暖彩手记 | `latte` | 暖灰纸张、玫粉标题、蜜桃色标题面板与紫色层级，适合教程与实验笔记 | 17px 正文、GitHub 浅色代码、阅读换行、表格自动适配 |

深海青、青绿实验室与旧版雅致/简洁/留白从常用列表收起。已有稿件使用这些版式时，选择器会追加一项“已保存 · 原版式”，原 ID、元数据与历史 revision 不做迁移；切回七套常用版式后收起该兼容项。共十二个文章版式 ID 继续兼容。

三套新增文章版式参考 [Nord 色板](https://www.nordtheme.com/docs/colors-and-palettes/)、[Dracula 配色规范](https://draculatheme.com/contribute)和 [Catppuccin 风格指南](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md)，将语义配色应用到整篇文章的标题、引用、提示框、表头与图注，并为小字号阅读调整颜色对比度。默认配色呈现各自完整设计，切换强调配色后仍保留文章纸张和结构。

AMD 技术蓝的默认强调色与“AMD 官网蓝”配色采用 ROCm 博客官方浅色链接蓝 `#0051C6`，暗色版式使用其暗色链接蓝 `#2899FF`，引用底色随明暗调整。来源：[官方样式表](https://rocm.blogs.amd.com/_static/custom.css?v=643846e8)。公众号参考文章仅借鉴标题、引用与留白层次，其暖橙配色未复制到技术蓝。

切换版式会加载该版式的推荐组合，随后可以单独调整八项排版设置。默认配色保留各版式的原设计；其他配色作用于标题强调、链接和相关边线，纸张由文章版式控制；代码主题可独立选择，不受标题配色影响。

## 八项排版设置

| 设置 | 可选值 | 用途 |
| --- | --- | --- |
| 正文字体 | 随版式、系统黑体、阅读宋体 | 随版式时，纸感期刊使用宋体，其余新主题使用黑体；实际字体取决于手机或电脑已安装的字体 |
| 正文字号 | 15、16、17、18px | 调整正文和列表文字；代码块继续使用等宽字体及独立字号 |
| 图片说明字号 | 12、13、14、15、16px，新主题默认 12px | 调整图片下方说明文字，最低 12px；旧三版式默认保留约 13px 的原有图注 |
| 表格字号 | 12、13、14、15、16px，新主题默认 13px | 调整表格及分行卡片内文字，最低 12px；旧三版式默认保留 16px，宽表格通过滚动或卡片显示完整内容 |
| 代码字号 | 12、14px，默认 12px | 每篇稿件独立保存；正文、表格字号不覆盖代码字号 |
| 代码主题 | 随版式、VS Code 深色、GitHub 浅色、Catppuccin 摩卡 | 三套独立代码配色，随稿件保存；随版式时技术蓝/曜石青/深海青/极光蓝绿使用 VS Code，紫夜实验室使用 Catppuccin，其余使用 GitHub |
| 代码长行 | 阅读换行（默认）、横向滚动 | 横向滚动保留长行形态；阅读换行适合手机阅读，不改写 Markdown 中的原始代码 |
| 表格呈现 | 自动适配、保留横滑、分行卡片 | 简单短表格可直接适配；宽表格可横向滚动；简单数据表可按每行生成带字段名称的卡片 |

代码块显示语言标记，并为支持的语言应用语法高亮，包括新增的 PowerShell 语法模块。未知语言按纯文本显示。

CSV、TSV、TXT、text、plaintext、plain 数据块直接按纯文本显示，不加行号或行号栏。Python、Bash 等代码块默认显示行号，每个原始逻辑行对应一个行号，空行也计数；长行在手机上自动换行时，续行不新增号码。行号采用独立窄列，随内容高度对齐；字号仍跟随 12/14px 代码设置。行号不写入 Markdown，使用不可选中的辅助标记，浏览器手动复制只保留代码；同步核对和双向滚动也排除行号。该复制行为已在本地 Chromium 实测，手机微信的选择行为仍以客户端实际效果为准。

代码块可选 12px 或 14px，默认 12px；行内代码和语言标记保持 12px。字号随稿件保存、恢复及文章包导入导出，正文和表格字号不覆盖代码字号。新稿件、缺失设置和切换版式默认阅读换行；已有稿件明确保存的横向滚动设置保留，可在“代码长行”切换为阅读换行。公众号导出使用显式 HTML 换行标记，并为行首缩进提供显示宽度；原始 ASCII 空格、Tab 和字符串内容不改写。十二套新旧版式共用此规则。

公众号预览和导出中的外部链接显示为“名称[编号]”的彩色下划线文字，完整网址移到文末“参考资料”，相同网址按首次出现去重。裸网址在正文缩为域名，文末保留原网址；长地址可换行，不撑宽正文。链接中的图片和格式化文字保留，Markdown 原稿、代码中的网址和文内脚注引用不变。语言栏采用真实 section 元素，分隔线落实在代码区顶边，发布所需样式均内联。

上表的“新主题”指 AMD 技术蓝、纸感期刊、极简墨色、曜石青、深海青、青绿实验室、极光蓝绿、紫夜实验室、暖彩手记。旧 `grace`、`default`、`simple` 的图片说明默认元数据为 13，保留原版式约 13px 的图注；表格默认元数据为 16。旧版式中将任一项选为 12px 都会明确应用 12px，并形成新的稿件 revision。

## 图片说明与表格

紧跟图片的 `*图 1：实验室架构。*`、`**Figure 1: Laboratory layout.**` 等编号说明，也会在预览和发布 HTML 中识别为图注，跟随图片说明字号。Markdown 原文保持不变，普通正文段落不会合并为图注。

图片说明优先取 Markdown 图片的显式 `title`，没有 `title` 时使用描述性的 `alt`。文件名形式的 `alt` 和图片路径不自动生成说明。例如：

```markdown
![多卡互联拓扑](images/topology.png "图 1：多卡互联拓扑")
```

上述图片的说明为“图 1：多卡互联拓扑”。`![topology.png](images/topology.png)` 不会把文件名显示成图片说明。没有说明文本时不额外生成占位文字。

自动适配优先利用实际可用宽度并允许单元格换行，普通两列表格在手机上也无需横滑；多列表格按列数和字号保留基本阅读宽度，仅当容器确实放不下时出现横向滚动条。切换手机、折叠屏、iPad 或横竖屏后会自动重新适配。该规则同时适用于已保存的旧版式，以及预览和公众号行内样式导出。

宽表格保留全部列和单元格内容，不用省略号或裁切隐藏内容。“保留横滑”保留不换行的单元格，适合逐列比较数据；分行卡片把简单表格的每行展开为带字段名称的记录，适合窄屏阅读。合并单元格、复杂表头、原文指定的列宽等结构保留为表格，不强行转换为卡片。

## 微信导出的行距与留白

本版按 [WeChatJS 文章结构验证规范](https://github.com/wechatjs/verify-article-structure-spec/blob/main/verify_article_structure.md) 检查行高重叠、固定尺寸裁切与终端字体差异，并把发布所需样式转为行内样式。规范没有规定所有文章必须使用某个统一行距；下面是发布器为技术文章选择的默认值。

| 元素关系 | 默认值 |
| --- | --- |
| 正文行高 | 字号的 1.8 倍 |
| 标题行高 | 字号的 1.45 倍，内部强调文字继承 |
| 正文段间 | 16px |
| 二级标题之前 / 其他标题之前 | 28px / 24px；连续标题 16px |
| 标题之后 | 12px |
| 图片、代码与相邻正文 | 20px |
| 图片与说明 | 8px，说明行高为字号的 1.65 倍 |

每个正文块只拥有一份前置留白，避免依赖相邻 margin 的折叠行为。图片使用块级显示，清除图内段落、图注的重复留白；清理常见导入行高与空占位段落，减少标题上下和图片说明附近忽宽忽窄的问题。正文黑体采用平台默认字体族优先，宋体和代码等宽字体保留各自设置。

规则用于九套新主题的预览和导出，旧三主题继续兼容加载；Markdown 原文、八项保存字段及历史 revision 不迁移。浏览器回归覆盖窄屏、折叠屏与 iPad，实际微信仍可能受客户端处理、系统字体、字号和深色模式影响，最终以微信草稿预览为准。

设备、方向和显示比例仅用于当前浏览器预览，不写入稿件、不同步到微信，也不改变八项排版设置。预览框架只在编辑器外层，导出/同步 HTML 不包含设备缩放、固定宽度或机型外壳。它用于检查排版，不模拟微信客户端字体、浏览器内核或真实折痕；最终效果仍需微信草稿预览确认。

## 双向同步滚动

预览工具栏的“⇅ 同步滚动”默认开启。滚动左侧 Markdown 编辑区会带动右侧预览，滚动右侧也会定位左侧；点击开关可独立查看。开关状态仅保存在当前浏览器，不修改稿件或排版元数据。

同步采用标题、段落、列表、引用、代码块、表格等对应内容块定位，块内按相对进度映射，减少图片与代码高度不同造成的偏移。图片区尺寸、设备宽度、方向或预览缩放发生变化时会重新计算；公众号预览和本站预览均支持。正文改变时，等待新预览完成后再同步，避免沿用旧映射。

到达顶部或底部时两侧同步到边界。代码与表格内部的横向滚动独立；滚动不改变光标、选区或保存状态，切换稿件后从顶部开始。对于不能精确匹配的自定义 HTML 或复杂组件，使用相邻已匹配块或全文进度作近似定位。

内容位置标记只添加在编辑器预览 DOM 中，不写入 Markdown、同步或导出的公众号 HTML。实现位于 `frontend/scroll-sync.mjs`，集成与缓存版本由构建器维护。

## 兼容范围

- 支持 Markdown 标题、段落、行内代码、代码块、列表、普通引用、链接、图片和表格；提示型引用可使用 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 标记。
- 分行卡片适用于结构规则的简单表格。合并单元格、多行表头、嵌套表格、表尾或各行列数不一致时，保留表格并采用横滑，避免改变单元格关系。
- 旧稿件明确保存的 `grace`、`default`、`simple` 主题继续可用。原有四项均为随版式字体、16px、代码横滑、表格自动适配，且新增图片说明/表格字号为其默认的 13/16 时，保留原有旧主题处理与历史 revision。
- 已部署的四字段记录会按主题补上默认元数据：旧三版式为图片说明 13、表格 16；`technical`、`journal`、`minimal` 为图片说明 12、表格 13。使用这些等效默认值时保持原 revision。修改新增字号会形成新 revision；恢复其主题默认值后恢复对应的历史哈希，不需要迁移或改写旧稿件文件。
- 排版设置会随稿件保存。当前八字段同步请求须完整，且与已保存的主题、配色和设置一致。旧七/六/四字段请求仅在缺失字段均为稿件对应默认值时兼容：`code_theme=auto`、代码字号 12px，图片说明/表格字号为旧三版式 13/16、新九主题 12/13。明确选择其他代码主题或字号后，缺失这些字段的旧请求会收到 409，避免旧客户端覆盖新设置。检查在上传素材和创建远端草稿前完成。旧主题采用全部默认排版时仍兼容缺省排版对象的旧请求。
- 设置只接受预设字体、字号、代码和表格模式，不接受任意 CSS。自定义 HTML 或自行插入的样式不在全面兼容承诺内。

维护接口共八个字段：`font_family`、`font_size`、`caption_font_size`、`table_font_size`、`code_font_size`、`code_theme`、`code_wrap`、`table_mode`。`code_theme` 只接受 `auto/vscode/github/catppuccin`，缺省为 `auto`；默认值不改写旧稿 revision。明确选择代码主题后，旧客户端遗漏该字段的同步请求会被拒绝，防止覆盖新设置。代码字号为 12/14px，缺省 12px，缺失长行设置时默认阅读换行。

当前资源由 `tools/build-frontend.mjs` 统一生成并附带内容哈希，版本为 `2026.10.22-code.6`。独立代码样式源文件为 `frontend/code-themes.mjs`，构建时同时输出独立模块与应用 bundle，发布所需样式内联到最终 HTML。

## AI 与 GPU 代码高亮

代码使用本地 Highlight.js 11.11.1，保留 Python/C++、AI/GPU 扩展及 PowerShell、Bash、Dockerfile、CMake、LLVM IR 等语法，无需联网加载。代码主题独立于文章模板：

| 代码主题 | 特点 |
| --- | --- |
| VS Code 深色 | 炭黑背景，紫色关键字、黄色函数、青绿色类型、蓝色变量，适合 AI/GPU 技术文章 |
| GitHub 浅色 | 浅灰背景，深红关键字、紫色函数、蓝色常量，适合白底文档 |
| Catppuccin 摩卡 | 深紫灰背景，柔和紫/蓝/绿/桃色层次，适合较长代码 |

三套主题细分 14 类语法角色，使用真实语言标题元素、独立标题底色、细分隔线和紧凑行号。代码字体为 12/14px，语言栏 12px，行高 1.8；每种语法颜色、正文、行号和语言栏均做至少 4.5:1 对比度检查。等宽字体按 JetBrains Mono、Cascadia Code、SFMono、Consolas、Liberation Mono、Menlo 等顺序回退，实际由阅读设备可用字体决定，不依赖远程字体。

设计参考 [VS Code 语法高亮机制](https://code.visualstudio.com/api/language-extensions/syntax-highlight-guide)、[VS Code Dark+ 配色](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_plus.json)、[GitHub 代码配色](https://github.com/highlightjs/highlight.js/blob/main/src/styles/github.css)与 [Catppuccin 风格指南](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md)。为适应手机上的小字号，部分颜色提高对比度。公众号导出只依赖真实 HTML 元素、内联颜色、显式换行和缩进宽度；不依赖 CSS 计数器、伪元素、远程字体或 JavaScript。

在 Markdown 的三个反引号后填写语言：

| 内容 | 推荐标记 | 兼容标记 |
| --- | --- | --- |
| Python / PyTorch | `python` | `py`、`python3`、`py3`、`pytorch`、`torch` |
| TileLang | `tilelang` | `tile-lang`、`tile_lang` |
| Triton | `triton` | — |
| C / C++ | `c` / `cpp` | `c++`、`cxx`、`cc`、`hpp` 等原有 C++ 别名 |
| AMD HIP | `hip` | `hip-cpp` |
| CUDA | `cuda` | `cu`、`cuh` |
| PowerShell | `powershell` | `pwsh`、`ps1`、`ps`、`psm1`、`psd1` |
| Bash 脚本 | `bash` | `sh`、`zsh` |
| 带 `$` 提示符的终端记录 | `shell` | `console`、`shellsession` |
| 容器与构建 | `dockerfile` / `cmake` | `docker`、`cmake.in` |
| LLVM IR | `llvm` | `ll` |

普通 `python` 代码块也会突出常见 PyTorch/NumPy/JAX/TensorFlow 命名空间、Tensor/constexpr 等注解。TileLang 的 `T.Kernel`、`T.copy`、`T.alloc_shared`，Triton 的 `tl.load`、`tl.store`、`tl.arange`，以及 HIP/CUDA 的内核限定符、线程索引和运行时 API 有专门识别。采用词法高亮，不进行类型推断；自定义命名空间别名可能按普通标识符显示。JavaScript/TypeScript、JSON/JSONC、YAML、TOML、Rust、SQL 等已有语言继续可用。

代码横滑保留长行，换行模式只改变显示；缩进、空行、制表符及尖括号等原文保留。公众号导出将颜色转成行内样式，不依赖网页脚本或高亮类名。未填写或不支持的语言安全显示为纯文本，不自动猜测。十二套文章版式共用新代码框、独立代码主题及 12/14px 字号设置；CSV/TSV/TXT 等数据块始终不显示行号。

## ROCm 博客转载

点击左侧“导入 ROCm 博客”，粘贴 `https://rocm.blogs.amd.com/` 官方文章链接。编辑器先保存当前修改，再建立新稿；不会覆盖正在编辑的正文。导入会选取文章正文，排除站点导航、侧栏与标题锚点；将相对链接解析为绝对地址，将正文配图下载到新稿的 `images/` 下，并保留图片说明、作者、原文来源和代码语言。

代码块保留原始缩进、空行、续行和字符；正文表格使用编辑器既有的自动适配、横滑或卡片模式。Sphinx 提示框转为提示型引用。仅访问同一官方博客主机，重定向也检查；图片下载失败则不保留半成品草稿。导入后的文章仍可正常编辑与翻译。

安装版已包含解析依赖。源码运行额外执行 `python -m pip install -r requirements-rocm.txt`，不需要为了博客导入安装浏览器归档工具。
## 微信手机端的表格策略

“智能适配”按内容选择呈现方式：简单的三列及以上说明表，如果正文包含长句，会按原行转为纵向信息卡，逐项保留列标题、内容、强调、链接和行内代码。两列参数表与短数值对比保留表格，使用写在单元格上的百分比列宽，避免某一列被自动列宽算法挤成细条。真正放不下的数值表保留横滑；明确选择“保留横滑”时不自动转卡片。合并单元格、嵌套表格、作者指定尺寸、图片或代码块等复杂表格继续保留其结构。

字号仍由 12–16px 表格字号控制，预览与导出使用相同策略；发布 HTML 不依赖 class、媒体查询或页面脚本。已有 Markdown 不会被改写。表格原有的局部字号、行距和间距覆盖会跟随信息卡保留，全局表格字号同样有效。

验收包括真实导出、12 套主题、12/13/16px 字号和 272–976px 文章宽度，以及去除部分布局属性后的保底检查。微信草稿接口回读只能证明平台保存的 HTML 和样式，不能代替手机端实际预览，特别是微信自行调整的深色模式。

参考：[markdown-nice 的逐列最小宽度和横滑容器](https://github.com/mdnice/markdown-nice/blob/master/src/template/basic.js)。本项目对长说明表采用完整行转卡片，减少对客户端表格布局差异的依赖。
